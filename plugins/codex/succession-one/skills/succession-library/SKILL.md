## Codex Handoff Rules

- Prefer MCP tool-returned full URLs (`url`, `route`, `library_url`,
  `source_url`, `crm_url`) in final answers so users can open them directly
  in Codex Browser.
- Use Browser automatically for app-visible create, update, and verification
  workflows when Browser is available in the Codex thread: after an MCP write,
  open the returned URL to confirm the change rendered, and use it to walk the
  user through UI-only steps this guide marks human-only.
- Never enter credentials, payment details, or approval decisions in Browser
  on the user's behalf; hand those steps back to the user.
- Ask concise follow-up questions when required context is missing; do not make
  the user know internal trigger, route, or table shapes.

## Workspace Routing

1. On the first Succession interaction, call `ping` without context.
2. If it returns `principal_type=workspace`, use Workspace-scoped tools
   normally. `client_id` is optional and cannot target another Workspace.
3. If it returns `principal_type=agency` (agency operators only), use
   Agency-scoped tools without `client_id`. Before client work, call
   `manage_managed_workspace` with `action="resolve_workspace"` and
   `params.query` set to the client name or UUID, then pass the returned
   `client_id` on every Workspace-scoped call, including
   `get_workspace_context`, `list_skills`, and `run_skill`.
4. Check `succession_context.workspace_name` in every result before relying
   on it. There is no persistent Workspace switch.
5. Tools take `action`, `params`, optional `client_id`, and `confirm`.
   Writes return a dry-run plan until they are called again with
   `confirm=true` after the operator approves. Read-only `read_*` aliases
   need no confirmation.



## Purpose

Library is the durable repository for artifacts, skills, agents, templates, and
source material that agents and operators reuse across workflows.

## When To Use

Use this when the user asks to find, open, create, update, organize, or reuse a
document, draft, source pack, skill, template, or artifact.

## Core Concepts

- Artifacts are durable and addressable.
- Library search should happen before recreating known work.
- Generated outputs that matter beyond the current chat belong in the Library.

## Available Actions

- Search library content.
- List, retrieve, create, or update artifacts.
- Discover and manage workspace skills.
- Return URLs for user review.

## MCP Tools And Actions

- Use `search_library` for semantic or metadata search.
- Use `list_artifacts` for browsing.
- Use `get_artifact` for full content and metadata.
- Use `manage_artifact` to create or update durable outputs.
- Use `list_skills` and `manage_skill` for skill library work.

## Workspace Skills To Discover

Look for skills only when the user asks for a repeatable action or when a
library artifact should be generated by a packaged workflow.

## URLs To Return

Return full absolute URLs for `/library`, `/library/artifacts`,
`/library/skills`, `/library/agents`, or `/library/templates`, plus the
specific `/library/:artifactId` URL from MCP tool responses when available.

## Approval Rules

Reading and creating drafts is safe. Publishing, external sharing, or changing a
skill that affects other operators requires confirmation and policy awareness.

## Artifact Rules

Prefer artifacts for drafts, reports, packs, campaign outputs, research briefs,
generated documents, and any output the user asks to view live in the app.

## Common Workflows

- Find material: search library, retrieve top artifacts, summarize relevance,
  and return URLs.
- Create artifact: produce the content, save with clear title and metadata, and
  open or return the artifact URL.

## Failure Modes

- Duplicate artifacts create confusion.
- Search result is semantically close but wrong workspace context.
- Artifact body is missing or stored externally.

## Human-Only Exceptions

Humans approve destructive artifact changes, external sharing, and workspace
skill changes that materially affect team behavior.

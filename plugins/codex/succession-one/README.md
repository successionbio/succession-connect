# Succession ONE Codex Plugin

Generated by `packages/connect/scripts/generate-codex-pack.mjs`.
Do not edit generated skills by hand.

The plugin bundles:

- surface guide skills generated from `docs/surfaces/guides/**`
- platform skill wrappers generated from `skills/platform/**`
- routing guidance for the production MCP connection named `succession-one`

## Install

The supported public marketplace is
`successionbio/succession-connect`. Install the complete plugin so both the
skills and bundled MCP declaration are registered together:

```bash
codex plugin marketplace add successionbio/succession-connect
codex plugin add succession-one@succession
```

1. Install `succession-one@succession`. Copying `skills/` alone does not
   install the MCP connection.
2. Let the plugin register its secret-free `succession-one` MCP declaration.
3. Start the MCP login flow, sign in to Succession ONE in the browser, and
   approve the exact Workspace shown. No token or HTTP header is copied.
4. Verify by calling `ping` without context through
   `succession-one`. Follow its `principal_type` and `next_step` fields.

For an API-token fallback or staging dogfood, run:

```bash
succession-connect codex --env staging
```

## How To Use

- Start with `$succession` for routing. It explains when to use primitive MCP
  tools, workspace skills, browser URLs, approvals, and artifacts together.
- Use `$succession-<surface>` for a focused product surface such as
  `$succession-campaigns`, `$succession-inbox`, or `$succession-library`.
- Use `$so-skills` when the right action is a workspace skill that must be
  discovered at runtime.

Every generated guide includes status, maturity, routes, primary MCP tools,
approval rules, artifact rules, common workflows, and failure modes.

# Succession ONE Claude Code Plugin

Generated by `packages/connect/scripts/generate-codex-pack.mjs`.
Do not edit generated skills by hand.

The plugin bundles:

- surface guide skills generated from `docs/surfaces/guides/**` (product
  surface knowledge + integrated-browser handoff rules)
- routing guidance for the production MCP connection named `succession-one`
- bootstrap slash commands in `commands/` (`/so-connect`, `/so-whoami`,
  `/so-help`)

Workspace and platform skills are intentionally NOT bundled here: Claude Code
discovers them live as MCP prompts (`/mcp__succession-one__<slug>` slash
commands, ADR-0057 Channel A), so they always match the connected workspace
without reinstalling the plugin.

## Install

The supported public marketplace is `successionbio/succession-connect`:

```bash
claude plugin marketplace add successionbio/succession-connect
claude plugin install succession-one@succession
```

1. Install `succession-one@succession` from that marketplace.
2. Open `/mcp`, choose `succession-one`, and start authentication.
3. Sign in to Succession ONE in the browser and approve the exact Workspace
   shown on the consent page. No token or Authorization header is copied.
4. If Claude Code asks for a restart, restart it, then verify by calling `ping` without context
   through `succession-one`. Follow its `principal_type` and `next_step`
   fields.

For an API-token fallback or staging dogfood, run:

```bash
succession-connect claude --env staging
```

## How To Use

- Start with the `succession` skill for routing across surfaces.
- Use `succession-<surface>` (e.g. `succession-campaigns`,
  `succession-inbox`, `succession-reporting`) for focused product-surface
  guidance: routes, primary MCP tools, approval rules, common workflows.
- Run workspace skills via their `/mcp__succession-one__<slug>` prompt commands,
  or `list_skills` -> `run_skill`.
- When the integrated browser is available, the guides direct verification and
  demo flows through live app URLs returned by MCP tools.
